日期：2026-11-15（Asia/Taipei）

状态：现状已检查；改版为待讨论建议，尚未修改产品代码。

## 当前实现

前端为原生 ES modules，无框架路由、无构建工具。`index.html` 加载 `styles.css` 和 `src/ui/main.js`。

```text
顶栏：品牌 / 最近五个会话 / 新建分析
├─ 首页：单商品输入 + 办公室模拟 + 教学案例
├─ 会话工作台
│  ├─ 商品标题 / 研究、学习、版本等状态
│  └─ 双栏
│     ├─ 主栏：办公室 → 六步拆解 → 初判对照 → 五维结论
│     │        → 下一步 → 业务证据与货源 → 利润与资金
│     │        → 教学练习 → 迁移练习 → 完整交付报告
│     └─ 右栏：初判 / 数据来源 / 数据问题 / 运行记录 / 证据教练
└─ 办公室动画演示：42 秒本地脚本，不含完整业务结果
```

内容会随会话数据隐藏，以上为代码中的完整顺序。`ui.tab` 仅控制交付成果内部的文档切换，工作台没有真正的页面分区。

### 主要问题

1. 等待研究、看过程、读结论、核证据、改成本、做练习和下载报告全部混在一页。
2. 已完成会话仍先显示办公室与时间线，结论需向下查找。
3. 320px 右栏同时放初判、来源、运行记录和提问；sticky 右栏与来源列表存在嵌套滚动。
4. 结构化结果后直接附完整 Markdown 报告，重复内容加重页面长度。
5. 顶栏仅展示最近五个会话，长商品名截断、同名难区分；720px 以下隐藏历史入口。
6. `main.js` 同时处理全局导航、会话状态、轮询、渲染和所有动作；`styles.css` 多轮覆盖同一选择器，布局职责分散。

本地实测：在 `http://127.0.0.1:4173/` 打开最近的已完成 adidas 商品会话，1280×720 视口下文档高约 8,735px，“结果页”距页顶约 1,635px；主栏约 867px、右栏 320px。数值仅代表本次内容和展开状态。

## 从用户旧项目借鉴什么

截图提供了明确的信息层级：固定侧栏管理产品模块；顶栏持续显示数据模式、模式切换与历史；作战室独立占据主视图；任务、协作场景、解读各有职责；播放与时间线集中在场景下方。

| 参考结构 | Pickwise 对应 | 处理方式 |
|---|---|---|
| 投研大厅 | 选品大厅 | 保持一个商品输入框，提供最近分析和预制演示入口 |
| 多 Agent 作战室 | 选品作战室 | 展示六步分析状态、现有办公室、当前步骤讲解 |
| 研究报告 | 分析报告 | 五维结论、判断依据、下一步与可下载报告独立呈现 |
| 投研课堂 | 学习中心 | 初判对照、教学练习、迁移练习、学习记录 |
| 股票库 / 行情等独立模块 | 证据与测算 | 只承接已实现的来源、竞品、趋势、货源、利润与资金能力 |
| 顶栏产品演示 | 全局演示模式 | 明确预制数据、案例切换、回放、退出实时入口 |

学习其结构和操作层级，保留 Pickwise 的绿色纸面风格、选品定位和已有办公室资产。侧栏不照搬尚不存在的专家中心、用户画像、行情和知识库模块。角色展示反映现有分析步骤，不据此声称已经有多个独立智能体并行运行。

## 推荐布局草案

### 全局框架

```text
固定侧栏（可折叠）
  Pickwise
  选品大厅 / 选品作战室 / 分析报告 / 证据与测算 / 学习中心

全局顶栏
  [实时分析 / 演示模式 · 预制数据] [案例] [切换模式] [历史记录]

作战室页头
  商品 + 当前研究状态 + 下一步操作

任务栏             主工作区                       讲解栏
六步任务流          现有电商办公室                 当前步骤一句话结论
当前任务摘要        简洁进度与真实步骤计数           为什么查 / 怎么读
数据覆盖摘要        时间线 / 演示播放控制             来源编号 / 局限
                    可展开的当前步骤详情             证据教练按需打开
```

左侧全局导航与任务栏分工不同：前者切模块，后者看当前商品的六步执行。避免把所有信息都做成新导航。

作战室承载过程；报告页承载结论；证据与测算页承载详细来源和可编辑条件；学习中心承载练习。主视图不再追加完整报告全文。已完成任务可直接进入报告；作战室保留可回看的过程。

### 宽度与滚动

- 用户截图是约 2549px 宽屏，不能照抄四列固定宽度到普通笔记本。
- 宽屏展开任务栏、场景、讲解三栏；桌面中等宽度把任务流压缩成横向步骤条，讲解按需展开。
- 窄屏保留可访问的导航，将场景、当前步骤、解读顺序排列，历史入口不直接隐藏。
- 正文以页面滚动为主；仅日志等明确的次级列表允许限高，避免来源列表再嵌套侧栏滚动。
- 默认视图、切换状态与 URL 可恢复，演示和真实任务状态互相隔离。

### 讲解栏内容来源

现有步骤卡已经有 `why`、`found`、`how_to_read`、`misread`、`scope` 和教学节点。将当前步骤这些内容映射到讲解栏，不需要为布局重新生成一套结论。模型尚未返回时显示等待或已取得证据，不填充虚构讲解。

## 预制演示模式预留

### 与当前 demo 的区别

`server/demo.js` 只有模拟证据和成本。`POST /api/demo` 会先 `needLlm()`，再运行真实研究流水线，讲解与结论仍调用模型。`?office-demo` 只是办公室动画。`test-support/ui-server.js` 的假模型是测试辅助，不是产品演示。

因此新布局中的“产品演示”需是完整数据模式，而不是现有按钮换名字。

### 数据与交互边界

- 在 `src/ui/api.js` 数据访问边界抽出 live/demo provider，向相同页面组件提供相同 view；不要复制两套页面。
- 案例包包含来源性质、观察日期、schema 版本、六步卡片、事件、证据、结论、成本、教学节点和三类交付内容。真实快照保留日期；人工案例标明教学模拟。
- 同一个预制案例支持直接看结果与过程回放；提供暂停、跳步、变速、重播、重置。脚本时间不冒充真实调用耗时。
- 全程展示“演示模式 · 预制数据”；无需模型/API Key，不调用外部模型或数据源。页面静态资源仍可由本地服务提供。
- 演示进入时停止真实轮询；不触发监控、立即采样、付费重跑或真实自由问答。provider 声明可用能力，有本地实现才开放。
- 成本试算复用确定性计算；演示预制文字若未同步重算则明确标为原案例结论，避免数字与解释冲突。
- 初判、练习、草稿、当前案例和历史与真实会话隔离；退出演示恢复真实工作区。重置仅影响演示状态。
- 导出包含演示标识与来源；不能将模拟结论包装成实时分析。
- 真实进度显示步骤状态或已完成步数；只有演示回放可显示脚本时间百分比。

## 其他可行方式

- 仅给现有长页添加目录：改动最少，但办公室、来源和报告仍混在一页，不作为推荐。
- 单线向导：层级最简单，但会限制自由查看，与既定的分析自动推进、不强制暂停原则不符。
- 推荐采用旧项目的应用框架加独立作战室，并按 Pickwise 的实际功能缩减模块。

## 后续验证重点

1. 普通笔记本也能清楚操作导航、当前步骤和讲解，无横向挤压或多重嵌套滚动。
2. 研究中、部分失败、证据不足、等待商品确认、重算、过期结论都有明确状态位置。
3. 演示无密钥可进入，完整覆盖过程、结论、测算、练习与交付，不产生真实模型或采集请求。
4. 演示切换、重播、重置不会修改真实会话；真实功能继续使用现有接口与确定性计算。
5. 现有办公室动画、人员移动和圆桌对称布局不因外层重排而改变。
